> **今日编辑判断**：先把 **scFoundry/practical boundaries** 与 **Scaling recipes** 连续读。前者问“预训练 representation 在哪些 biological tasks 真有用”，后者问“pretraining loss 在哪些 formulation 下能随 compute 可预测地下降”。两者并不矛盾：优化目标可以稳定 scale，而 downstream effect size 仍然接近零。统计遗传学方向则优先读 **Dynema**，尤其是 donor 作为 cluster 的推断逻辑。

## 两种“scaling”不能混为一谈

单细胞 foundation model 至少有三条不同的 scaling curve：

1. **optimization scaling**：compute 增加时 held-out pretraining loss 是否下降；
2. **scientific utility scaling**：下游 annotation、open-set、spatial 或 regulatory task 是否改善；
3. **systems scaling**：多 GPU、数据管线与显存是否带来接近线性的 throughput 增益。

Scaling recipes 主要研究第一条；scFoundry 主要检验第二条，并提供可复现部署基础设施。不能由第一条直接推出第二条，也不能把容器化部署等同于第三条。

## scFoundry 为什么属于“资源”，而不是“算法加速”

scFoundry 使用 Nextflow 与 pinned containers 统一运行多个 scFMs、传统方法和 representation-geometry probes。这对 reproducibility、依赖管理与 HPC portability 很重要，但它本身不代表模型 kernel 更快。

本站以后只在有以下证据时标记“算法加速”：

- 明确的复杂度或算子改进；
- 固定工作量下的 wall-clock/throughput；
- memory 与数据搬运统计；
- 同等数值误差或 downstream quality；
- 硬件数量和型号透明。

## Dynema 与 fine-mapping 的关系

Dynema 的 Poisson + donor-clustered robust variance 解决 cell-level association inference；SuSiE 等 fine-mapping 方法解决 locus 内 LD 与多 causal signals。两者不能互相替代。

合理的整合需要：

1. 明确 context-specific effect 与 standard error；
2. 估计 variant 间及 contexts 间的 summary-statistic covariance；
3. 使用 ancestry-matched LD；
4. 多信号 fine-mapping 后再做 signal-aware colocalization；
5. 将 cell-state 或 sequence-model score 作为需外部校准的 functional prior。

尤其不能把 `number of cells` 直接作为 SuSiE/coloc 的 sample size。真正携带独立 genotype variation 的仍然是 donors。
